## 1. Внутренняя система обработки заявок университета

Единая система подачи, маршрутизации и согласования заявок студентов и сотрудников (справки, общежитие, заявки, закупки) вместо e-mail и бумажных заявлений.

**Бизнес-анализ**
- Опросник для интервью: 68 вопросов от 3 ролей стейкхолдеров в 12 категориях
- Документ о концепции и границах проекта
- Бизнес-требования с измеримыми целями: время обработки обращений −30–50%, доля просроченных заявок не выше 15%
- Пользовательские требования для 5 ролей, постановка на экранную форму

**Системный анализ**
- 17 сущностей с атрибутами и операциями
- REST API: эндпоинты и детальные постановки на методы (UML Sequence и Activity, алгоритм обработки, валидации и коды ошибок, JSON-примеры, маппинг полей API и БД)
- ER-диаграмма, нормализация до 3НФ, постановка на таблицы PostgreSQL

## 2. Личный кабинет ученика (дипломный проект)

Модуль для образовательного центра подготовки к ОГЭ/ЕГЭ. Архитектура: SPA, API Gateway, Core-сервис на PostgreSQL, адаптер LMS Moodle (headless), сервис уведомлений на Apache Kafka, файловое хранилище.

- AS-IS: учёт в таблицах и бумажных журналах, ручные рассылки родителям
- BPMN пути ученика, User Stories с Acceptance Criteria, Use Case
- REST API личного кабинета в OpenAPI
- События Kafka для SMS-уведомлений родителям и сквозной сценарий в UML Sequence

## 3. Кейс: регистрация и авторизация

Требования для бэкенд-разработчика, необходимый набор эндпоинтов (пользователь, токен подтверждения, сессия), параметры и коды ответов, постановки задач на операции: «Регистрация пользователя» и «Подтверждение почты».
